# 小车台账

用于小车量产管理的中文本地台账：记收支、管逐套库存、配对车辆、登记出货，并保存门店账号与安装资料。当前版本为 **v1.2.0**。

程序在这台电脑上运行，使用浏览器操作，数据保存在项目目录。上传到 GitHub 的是程序源码；GitHub 不会因此成为台账服务，也不会同步你的业务数据。

## 1. 能做什么

| 页面 | 主要用途 |
| --- | --- |
| 总览 | 查看实际收入、实际支出、收支差额、配件库存和车辆状态 |
| 收支账本 | 分类记账，保存购买截图、发票等附件，筛选查询与预览 |
| 入库与库存 | PCBA、结构件分别入库和出库，每套配件有独立编号 |
| 车辆档案 | 车架号绑定 PCBA 号，追溯装车、换板、出货与转店 |
| 出货记录 | 一次登记多辆整车或门店备件，保留去向与历史 |
| 门店档案 | 门店编码、联系方式、车辆、加密账号备忘、安装资料 |
| 设置与备份 | 解锁、修改密码、完整备份与恢复、切换演示台账 |

当前面向单机使用。暂不提供云端同步、多用户权限、手机远程访问、应收应付核算或地图参数编辑。扫码入口支持输入编号后回车的键盘式扫码枪，也可手输；没有手机摄像头扫码功能。

## 2. 安装与启动

### 准备环境

- Windows 电脑、64 位 Python 3.13、桌面浏览器。
- 首次安装依赖需要联网，安装完成后日常使用可离线进行。
- 源码可通过 Git 克隆，也可在 GitHub 下载 ZIP 后解压。

使用 Git 下载：

```powershell
git clone https://github.com/dengxiangjie12138/car-ledger.git
cd car-ledger
```

在项目目录打开 PowerShell，创建独立环境并安装依赖：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\启动小车台账.cmd
```

`requirements.lock.txt` 固定当前依赖版本，便于复现环境。项目不需要 Node.js、前端构建或单独安装数据库。

### 日常打开与关闭

双击项目内的 **启动小车台账.cmd**。也可给它创建桌面快捷方式，命名为 **小车台账**。已有桌面入口的电脑直接双击即可。

启动器会在后台启动本机服务，自动选择空闲端口并打开默认浏览器。重复启动会复用本程序的服务，不需要记住端口。

关闭网页不会停止后台服务。需要停止时，在“设置与备份”中选择停止本地服务；下次双击入口可以重新启动。启动异常时查看 `logs/server.log`。开发排错也可以在终端直接运行：

```powershell
.\.venv\Scripts\python.exe server.py --port 0
```

终端会显示本机访问地址；此方式可用 Ctrl+C 停止。服务只监听 `127.0.0.1`，不需要把它开放到局域网或公网。

## 3. 第一次使用

1. 新安装默认提供独立的**演示台账**，初始记录为虚构示例，可以先试录入、出库和出货。试操作也会保存。
2. 切换到**正式台账**，设置至少 8 个字符的解锁密码。正式台账从空记录开始。
3. 下载或抄写生成的**恢复密钥**，在台账目录以外单独保管，按页面提示确认已保存。
4. 按需要建立门店，然后登记配件、装车和出货。收支可以独立录入。

演示和正式数据分开保存，不会把演示数据自动带入正式台账。后续打开会记住上次选择的台账。密码或恢复密钥不要写进源码、提交到 GitHub 或放进公开截图。

### 用 10 套配件走一遍

以下编号只用于说明；可以在演示台账换用未重复的编号练习。

1. 点击 **PCBA入库**，登记 `P001` 至 `P010`，一行一个编号。
2. 点击 **结构件入库**，登记 `F001` 至 `F010`。结构件编号就是车架号。
3. 分别通过 **PCBA 出库**、**结构件出库**，选择“装车领用”，确认领用各 3 套。
4. 在车辆档案组成 3 台车，例如 `F001 ↔ P001`、`F002 ↔ P002`、`F003 ↔ P003`。
5. 建立一家门店，登记这 3 台整车出货。
6. 仓库可用 PCBA 和结构件应各剩 **7 套**。整车出货不会再扣一次配件。
7. 如果实际支付了配件款，到收支账本单独记支出；上述入库、领用和出货不会自动生成账目。

## 4. 收支怎么记

点击 **记一笔收支**，填写方向、金额、日期、分类、备注，需要时添加附件。

| 方向 | 分类选项 | 显示颜色 |
| --- | --- | --- |
| 收入 | 甲方回款 | 红色 |
| 支出 | PCBA采购、结构件采购、研发耗材、吃饭、差旅、出货耗材 | 淡绿色 |

分类随方向切换，通过选项选择。当前没有自定义分类设置；后续需要新分类时再扩展。金额使用人民币，必须大于零，最多两位小数。

表单保留一处备注，用来自由记录背景，不再要求填写往来方、关联门店、采购批次或用途事由。第一版留下的历史分类仍可原样保留；历史用途可在备注摘要中查看。

只记录**实际收款、实际付款**。入库表示配件到了，付款表示钱付了，两者独立，避免同一笔采购在两个地方重复统计。首页的“收支差额”是收入减支出，不代表利润，也不计算应收应付。

账本支持搜索分类和备注、筛选方向与分类、限定日期范围。普通账目可编辑；记错的账目可作废，原记录保留但退出汇总。

### 截图、发票与悬停预览

- **选择文件**：在附件区域选择图片、PDF 或其他文件。
- **拖入文件**：将文件拖到附件区域。
- **粘贴截图**：复制图片后，在附件区域按 Ctrl+V。粘贴的是剪贴板图片，不是文件路径文字。
- **保存前检查**：待上传清单支持预览和移除选错的文件。
- **列表直接预览**：在收支账本主列表，把鼠标放到“附件 N 份”上，会主动打开预览；多份附件可以切换，PDF 可以翻页。
- **详情预览**：详情附件列表也支持悬停与预览按钮。其他类型文件可以下载。

单个文件最大 **50 MiB**（界面简写为 50 MB）。支持预览的图片格式为 PNG、JPEG、GIF、WebP；PDF 使用随程序提供的 PDF.js 在本地渲染。右侧详情打开后，点击左侧遮罩空白处即可关闭，也可使用关闭按钮。

若账目已保存但附件上传失败，按提示重试即可；程序会复用已保存账目和上传请求，避免因重试重复记账。不同文件即使文件名和大小一样，也不应互相覆盖。

## 5. 入库、出库与库存

### 入库

**PCBA入库**和**结构件入库**是两个独立入口，入口已固定配件类型。填写日期、编号和备注即可，不需要供应商或本批采购金额。

编号可连续扫码、手输或按行批量粘贴，一批最多 1000 个。编号按文本保存，保留前导零和大小写；同一类型内不能重复。例如 PCBA 的 `0001` 不会变成 `1`。

数量由有效编号数量确定。入库只管理实物，不记采购成本，不生成付款记录。底层保留批次，是为了追溯哪些配件一起入库。

### 出库

1. 进入对应类型的出库入口。
2. 选择用途：**装车领用**，或指定门店的**门店备件**。
3. 扫描编号后回车，或手动搜索并加入待确认清单。
4. 核对清单，最后确认出库。

扫码加入清单不会立即扣库存。重复扫码、非在库编号和重复确认会被拦截；两个窗口同时操作时，由后端重新检查状态，避免同一套配件出库两次。

| 配件状态 | 含义 |
| --- | --- |
| 在库可用 | 可继续出库的仓库配件 |
| 已领用待装车 | 已从仓库领用，但尚未配成车辆 |
| 已安装 | 正绑定在车辆上 |
| 门店备件 | 已发往指定门店、尚未安装 |
| 待返修 | 需要后续处理的配件 |
| 已报废 | 不再作为可用库存 |

退库、返修、报废和备件调拨都记录流水。实际状态发生变化后，用后续业务操作更正，不直接擦掉已完成的出库历史。

## 6. 车辆、换板与出货

### 配成车辆

PCBA 和结构件可以分开领用，之后再用车架号绑定 PCBA 号。车架号作为车辆身份，一块 PCBA 同时只能绑定一辆车。未配对完成不能作为整车出货。

仓库领用的配件装车后成为待出货成品车；同一门店已有的配件也可按门店场景组成车辆。不同门店的配件不能直接混配。

### 整车出货与转店

选择日期、门店和已配对车辆，可以一次出多台，添加备注与附件。整车出货记录车辆和去向，不再扣配件库存。门店档案可以查到车辆及对应 PCBA。

车辆转店使用转店操作，记录原门店、新门店和日期。门店备件调拨同样保留去向；跨店使用备件时先调拨到目标门店。

### 换板

打开车辆档案选择换板，填写新板、日期、原因，并明确旧板去向：**待返修、退库、留店备件、报废**。

仓库车辆使用已领用的新板；已出货车辆使用当前门店已有备件。当门店备件安装到当地车辆时，不再次扣仓库库存。换板后保留旧号、新号和原因，可继续追溯历史。

只有明确退库，旧板才重新进入仓库可用量。第一版没有换车架流程。

### 误操作如何更正

尚未出货且没有后续变化的装车可撤销，配件回到已领用待装车状态。出货只有在相关车辆、配件没有后续操作时才能撤销。撤销会保留原记录和原因；发生后续变化时，应通过换板、转店、退库等操作处理。

## 7. 门店资料怎么保存

### 基础资料和自填编码

门店名称、编码、联系人、电话、地址、普通备注分别填写。**门店编码由使用者自行填写**，用于与将来的外部云平台对应；非空编码不可重复，保留前导零与大小写，修改编码不改变车辆和历史归属。

编码暂时可以留空。它不是列表顺序号，也不是内部数据库 ID；当前版本尚未对接外部云平台。

### 加密账号备忘

进入门店的 **账号备忘**，打开一份空白自由文档，自行组织路由器、Wi-Fi、远程控制账号、密码和说明。例如：

```text
路由器
Wi-Fi 名称：示例网络
密码：在这里填写

远程控制
账号：在这里填写
使用说明：在这里填写
```

账号备忘最多 40000 个字符，正文加密保存，打开时才读取。联系人、电话、地址仍保留独立字段。请把密码写在账号备忘里，不要写进普通门店备注或附件名称。

从旧版本升级时，首次打开可将已有结构化账号整理成文字供编辑；保存后以自由文档为准，原始旧记录继续保留。保存空白文档表示清空当前备忘，不会再次自动带入旧账号。

文档需要点击保存，未保存关闭会提示。请及时保存；会话锁定会清除当前打开的敏感正文，不能依赖未保存草稿长期保留。

### 安装资料

按资料项归档，例如“安装图”“地图参数”“安全池参数”，可添加多项文件和说明。地图与参数文件只保存和下载，不解析或编辑。

同一家门店更新同一资料项时替换原文件。新文件保存成功后才替换引用，失败保留旧文件。界面不提供旧版本浏览；若需要保留历史，请另建不同资料项或提前导出备份。

## 8. 密码、备份与恢复

正式台账的业务接口、附件和备份下载都需要解锁。可以主动锁定，长时间未操作也会锁定。服务端解锁有效期按 API 请求活动计算，约 30 分钟；长时间只输入未保存文档也可能需要重新解锁。

门店账号备忘与旧版账号内容使用 AES-GCM 加密。普通账目、联系方式和附件不加密，备份 ZIP 也不是加密压缩包。程序目录和备份应按财务资料保管。

### 导出完整备份

在设置中导出 ZIP，包含数据库一致快照、当前有效附件及加密密钥封装，不包含明文解锁密码或明文恢复密钥。建议定期复制到另一块磁盘，尤其是在恢复或升级之前。

安装资料替换后不保留可浏览旧版，但之前导出的完整备份仍可能包含当时的旧文件。

### 从备份恢复

1. 先导出当前台账，保留恢复前副本。
2. 在对应台账中选择恢复 ZIP。演示备份与正式备份不能混用。
3. 正式备份填写备份当时的密码或恢复密钥，并确认替换当前台账。
4. 程序检查数据库、附件和加密内容后才替换。校验失败不覆盖当前记录。
5. 正式台账恢复成功后，使用该备份对应的密码重新解锁；若只掌握恢复密钥，可使用忘记密码流程。

当前恢复上限：ZIP 文件及解压总量各不超过 2 GiB、数据库不超过 256 MiB、单附件不超过 50 MiB、ZIP 条目不超过 25000。

### 忘记密码

在解锁页选择“忘记密码？使用恢复密钥”，输入恢复密钥并设置新密码。成功后会生成新的恢复密钥，请重新单独保管。

修改当前台账密码不会改变旧备份的密码。密码和恢复密钥都遗失时，加密账号内容无法恢复。普通备份不代替单独保管恢复密钥。

## 9. 数据存在哪里

```text
car-ledger/
├─ 启动小车台账.cmd       # Windows 启动入口
├─ launcher.py            # 启动或复用本机服务
├─ server.py              # 本机 HTTP API
├─ store.py               # SQLite 和业务规则
├─ vault.py               # 账号加密与恢复密钥
├─ archive.py             # 完整备份和恢复校验
├─ static/                # 网页和本地 PDF.js 资源
├─ tests/                 # 使用隔离数据的自动测试
├─ docs/                  # 设计与需求演进说明
├─ data/                  # 首次启动生成，不提交 Git
│  ├─ live/               # 正式台账
│  │  ├─ ledger.sqlite3
│  │  └─ attachments/
│  ├─ demo/               # 独立演示台账
│  └─ server.json         # 当前服务地址和进程信息
├─ logs/server.log        # 启动与运行日志，不提交 Git
└─ .venv/                 # 独立 Python 环境，不提交 Git
```

更新源码时保留 `data/`，不要用空目录覆盖它。`.gitignore` 已排除数据库、附件目录、日志、备份、恢复密钥文件、虚拟环境和本机截图。发布前仍应检查待提交清单，不要强制添加这些文件。

## 10. 常见问题

**双击入口没有打开网页？** 先确认已安装依赖且 `.venv` 存在，再查看 `logs/server.log`。可以用前面的终端启动命令看到错误信息。

**网页地址的端口变了？** 正常，启动器自动寻找空闲端口；重新双击入口即可打开当前地址。

**库存为什么没减少？** 检查是否仅把编号加进待确认清单，或在看演示台账。只有确认出库才改变库存；整车出货不重复扣库存。

**入库为什么没有记支出？** 库存和现金账独立。到收支账本登记实际付款。

**附件不能预览？** 图片和 PDF 才有内置预览；其他文件使用下载。检查文件是否完整，以及当前台账是否已解锁。

**另一台电脑能否直接访问？** 当前服务只供本机访问。迁移时在新电脑安装程序，通过完整备份恢复，不要直接共享正在使用的数据库。

运行自动测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前包含 53 项测试，覆盖库存与车辆追溯、重复请求、账号加密、HTTP 访问控制、附件归属与备份恢复等。测试使用隔离目录，不需要正式台账密码。界面的悬停、扫码枪、拖放与常见桌面布局还需要交互检查，自动测试不替代这些检查。
